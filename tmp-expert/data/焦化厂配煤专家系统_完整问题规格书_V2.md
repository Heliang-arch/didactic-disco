## 第0章 快速入门：5分钟理解配煤专家系统

### 0.1 这个系统解决什么问题

焦化厂的核心生产是把**多种不同的煤**按一定比例混合后送入焦炉炼成焦炭。配煤专家系统就是帮助工程师回答三个问题：

1. **用哪些煤、各占多少比例？**（配比优化）
2. **这样配出来的焦炭质量合格吗？**（质量预测）
3. **库存够不够用、什么时候该采购？**（库存水位线与排程）

### 0.2 核心业务流程（一图看懂）

```
供应商发煤 → 进厂质检 → 煤场堆放(库存) → 取煤配煤 → 粉碎混匀 → 入炉炼焦 → 焦炭质检
                ↓              ↓              ↓                                  ↓
            单煤质量数据    库存水位线      配比方案(优化)                    实测质量
                ↓              ↓              ↓                                  ↓
                └──────────────┴──────→ 质量预测(数学模型) ←──────────────────┘
                                                     ↓
                                              预测 vs 实测对比
                                                     ↓
                                              修正模型系数(闭环)
```

### 0.3 关键概念速查表（不懂工艺先看这个）

| 概念 | 通俗解释 | 单位 |
|---|---|---|
| 单煤 | 一种单独的煤，如"山西主焦煤""澳洲肥煤" | — |
| 配合煤 | 把多种单煤按比例混合后的煤 | — |
| 配比 | 每种单煤在配合煤中占的百分比，总和=100% | % |
| 干基 | 把煤烘干去掉水分后的质量（计算配比用干基，消除水分波动影响） | — |
| 湿基 | 煤实际含水时的质量（现场下料用湿基） | — |
| Ad（灰分） | 煤烧完剩下的灰，越低越好，几乎全部进入焦炭 | % |
| St.d（全硫） | 煤中的硫，约70%进入焦炭，越低越好 | % |
| Vdaf（挥发分） | 煤加热后挥发掉的部分，影响化产品产量和焦炭强度 | % |
| 水分（Mt） | 煤中的全水分，用于干基/湿基换算 | % |
| FCad（固定碳） | 空气干燥基固定碳，可由Ad+Vdaf+Mad推算 | % |
| G（粘结指数） | 煤把其他煤粘在一起的能力，0-100+，炼焦核心指标（**本版本忽略**） | — |
| Y（胶质层厚度） | 煤加热后形成的胶质体厚度，与G共同决定焦炭强度（**本版本忽略**） | mm |
| X（最终收缩度） | 胶质层固化后收缩度（**本版本忽略**） | mm |
| M40 | 焦炭抗碎强度，越高越好（>40mm颗粒占比） | % |
| M10 | 焦炭耐磨强度，越低越好（<10mm颗粒占比） | % |
| CRI | 焦炭反应性，越低越好（与CO2反应的失重率） | % |
| CSR | 焦炭反应后强度，越高越好 | % |
| 成焦率 | 1吨干煤能炼出多少吨焦炭 | % |

## 第1章 系统总体架构

### 1.1 系统定位

配煤专家系统是焦化厂的**决策支持与数据管理平台**，不直接控制生产设备，而是为配煤工程师提供数据、预测和优化建议。核心原则："以销定配、以配保质"——根据焦炭销售合同的质量要求，反推需要什么样的配合煤，再反推用哪些单煤配比。

## 第3章 基础数据模块

### 3.1 煤种字典（CoalKind）

**做什么**：维护煤种的两级树形分类编码。  
**为什么做**：所有煤质数据、库存、配比都需要挂到统一的煤种编码上，是数据勾稽的基础。

**数据结构**：
- 大类（2位编码）：如"01"焦煤、"02"肥煤
- 小类（4位编码）：如"0101"焦煤1
- 编码自动递增
- 删除大类时级联删除全部下级小类

**配煤结构统计用七大煤类归并**：

| 煤类 | 编码简称 | 归类规则（按煤种名称关键字） |
|---|---|---|
| 肥煤 | FM | 名称含"肥"且不含"1/3" |
| 主焦煤 | ZJ | 名称含"主焦"或"焦煤"且不含"1/3""瘦" |
| 1/3焦煤 | J1_3 | 名称含"1/3焦" |
| 瘦煤 | SM | 名称含"瘦煤"且不含"贫""焦" |
| 弱粘煤 | RN | 名称含"弱粘" |
| 瘦焦煤 | SJ | 名称含"瘦焦" |
| 气煤 | QM | 名称含"气煤" |

另统计**国产煤(GC)/进口煤(JK)**比例：名称含"进口"归为进口煤，否则国产煤。

> 注意：关键字独立判断，一个煤名可能命中多个类别，结果不归一化（按设计说明书§5.7）。

### 3.2 煤归类（CoalToKind）

**做什么**：把每一个具体进厂煤（矿点煤/合同煤）映射到唯一煤种小类。  
**为什么做**：形成"煤名→煤种→煤编码"的桥梁，是全系统数据勾稽的核心。

**业务规则**：
- 煤编码规则：8位 = 4位煤种编码 + 4位流水
- 煤名全库唯一
- **删除保护**：该煤名已有进厂煤质检数据时禁止删除
- **联动更新**：煤名变更或调整归类时，同步更新质检历史数据中的煤名与煤编码

### 3.3 价格管理（CoalPrice）

**做什么**：按"煤名+日期"维护煤价。  
**为什么做**：配比优化的目标函数需要煤价计算成本。

**业务规则**：
- 既可挂在单煤上，也可挂在煤种上（保存时先按煤种名匹配、再按煤名匹配）
- 配比明细中同时记录**财务价(CaiPrice)**与**到场价(DaoPrice)**两个价格快照
- 配合煤加权成本 = Σ(价格 × 配比) / 100
- 化产品价格（PriceProduct）单独按日维护：电、焦油、粗苯、硫铵、煤气、焦粉、焦丁、焦炭共8项，作为配比优化收益函数的价格系数

> **当前数据状态**：附件中未包含煤价数据，系统上线时需从价格管理模块导入或人工录入。

### 3.4 焦炭合同指标（ContractCoke）

**做什么**：按炉组逐日维护客户合同要求的焦炭目标指标。  
**为什么做**：这是"以销定配"的约束来源——配比规划与质量预测均以最新合同指标作为质量合格判定边界。

**炉组划分**：
- 1#2#焦炉（一期）
- 3#4#焦炉（二期）
- 5#6#焦炉
- 7#8#焦炉

**维护指标**：M40、M25、M10、CSR、CRI、Ad、V、S

### 3.5 煤质评价（CoalAssess）

**做什么**：以PDF文档形式按煤名归档《煤质评价》资料。  
**为什么做**：供应商/煤种综合评审结论的人工归档，系统不内置扣分算法。

**功能**：上传、替换、在线预览、按"仅有库存的煤"过滤。

## 第4章 质检管理模块

### 4.1 进厂煤质检（JCM / JCMQY）

**做什么**：记录每批次进厂煤的化验结果。  
**数据来源**：以查询外部系统为主（MES检验委托+分析值，限定"焦化煤"品名与"JS"样品类型，含批次号、发货单位、发站、合同号、过磅重量）与ERP原料台账视图；本地录入为辅。

**进厂煤取样快检（JCMQY）**：
- 按日期批量录入当日快检指标，首屏只录5项：**Mt、Ad、Vdaf、St.d、G**
- Y、X、b、R、CRI、CSR、价格在后续修改环节（含"送审"操作）补录

**去重规则**："日期+Ad+V+S+G"五项全同视为同一条记录，重复录入时询问是否替换。

**统计口径**：
- 按煤名分组的期间统计采用**车数/重量加权平均**：Σ(指标×权重)/Σ(权重)
- 单项指标为0或空的记录不计入该项权重
- 经验估重规则：车牌含"鲁"字按10吨/车，其余按20吨/车

### 4.2 单仓煤质检（DCMQY）

**做什么**：煤入储煤仓后，按"仓号+煤名+日期"录入化验结果。  
**为什么做**：跟踪每个仓的煤质变化，是配比录入时各仓煤质指标快照的直接来源。

- 指标体系与进厂煤一致
- 同样采用"日期+四项指标"去重替换规则

### 4.3 配合煤（入炉煤）质检（RLM）

**做什么**：记录入炉配合煤的实测指标。  
**数据来源**：外部（MES/ERP检验），本系统不设录入界面，仅负责查询、多班平均及与配比单的挂接。

**记录指标**：Mt、Ad、Vdaf、St.d、G、Y、X、细度、T1~T3温度、班次等。

**MES取数条件**：配合煤品名代码 + 取样点 + 焦线（1~5线），剔除无检验结果的采样单。

### 4.4 焦炭质检（PBCoke）

**做什么**：按"日期+炉组期号"录入焦炭化验结果。  
**记录指标**：Mt、Ad、Vdaf、St.d、M40、M25、M10、焦末、CRI、CSR、焦重。

- 同期号重复录入时询问是否替换
- MES侧焦炭检验另含K2O、Na2O，统计窗体派生"碱金属合计"指标

### 4.5 质检数据查询

提供按日期段、煤种、品名、批次的多条件查询，支持网格明细+均值/极值汇总行+单指标趋势图（折线图），统计行支持双击钻取到批次级明细。

### 5.2 库存水位线模型

**做什么**：按煤种分级设定库存阈值，实时监控并触发预警。  
**为什么做**：防止断料（影响生产）和胀库（煤场溢出、煤料自燃）。

**核心公式**：
```
库存当量(天) = 当前库存量(吨) ÷ 该煤种日均消耗量(吨/天)
```

**四级水位线定义**：

| 等级 | 库存当量 | 颜色 | 触发动作 | 响应时限 |
|---|---|---|---|---|
| 最高库存线 | ≥25天 | 红色(胀库) | 暂停该煤种后续发货；启动煤场翻堆降温防自燃 | 24小时内 |
| 预警库存线 | 10–15天 | 蓝色(正常) | 正常管控；每日跟踪在途到货进度 | 每日核对 |
| 安全库存线 | 7–10天 | 黄色(预警) | 催促在途加快到货；启动备用供应商预案 | 48小时内 |
| 最低库存线 | ≤5天 | 红色(断料) | 启动应急配煤方案；调整配比；厂级调度介入 | 立即响应 |

**日均消耗量计算**：
```
净消耗量 = 期初库存 + 期间到货 - 期末库存
日均消耗量 = 净消耗量 ÷ 天数
```

> 基于2026.9.2–9.7实际数据：总库存从1,354,081吨降至239,099吨，6天毛消耗1,114,982吨，日均约222,996吨（约22.3万吨/天）。各煤种日均消耗详见附录A.1。

**水位线参数配置**：
- 按煤种分别配置，主焦煤、肥煤等关键煤种安全库存线应高于普通煤种
- 每季度复核调整
- 极端天气（汛期、冬季冻煤、台风）期间，关键煤种安全库存线上浮至12天

### 5.4 进销存排程测算

**做什么**：按日推演未来N天（默认15天）各煤种库存变化，识别断料风险。

**核心公式**（对每个煤种c、每一天t）：
```
库存(c, t) = 库存(c, t-1) + 到货(c, t) - 消耗(c, t)
```

**到货量(c, t)**：来自船运在途和铁运在途的预计到厂日。
- 船运：预计到厂日 = 推算到港日 + 卸船周期(2天) + 转运到厂(1天)
- 铁运：预计到厂日 = 发出时间 + 铁路运输周期

**消耗量(c, t)** 两种模式：
- **模式A（历史均值）**：使用近7天日均消耗量，适用于快速排程
- **模式B（配煤驱动）**：日消耗量 = 当日配合煤总产量 × 该煤种干基配比 × 干基/湿基换算系数，适用于精确排程

**排程硬约束**：
1. 库存非负：库存(c, t) ≥ 0
2. 最低库存：关键煤种任意天库存当量 ≥ 最低库存线（默认3天）
3. 到货量 ≤ 在途预测到货量（不可超量）
4. 煤场容量：单煤种库存 ≤ 煤场最大堆存容量

**排程输出**：15天进销存表（日期/煤种/期初/船运到货/铁运到货/消耗/期末/库存当量/水位线状态）+ 断料风险预警清单。

### 5.5 采购建议生成

当排程推演发现某煤种将跌破最低库存线且在途不足以补充时：
```
建议采购量 = (最低库存线当量 - 排程周期末库存当量) × 日均消耗量 + 安全裕量(默认10%)
建议到货日 = 断料风险日 - 采购运输周期
```

## 第6章 配比管理模块

### 6.1 四类配比对比

| 配比类型 | 业务含义 | 使用场景 | 单号规则 |
|---|---|---|---|
| 生产配比（实际配比） | 当班实际执行的配煤方案 | 生产指挥 | SJ+yyyyMMdd+4位序号 |
| 人工配比（预测配比） | 技术人员离线试算的方案 | 方案比选，不直接指导生产 | YC+yyyyMMdd+4位序号 |
| 配比规划（优化配比） | 在人工配比基础上自动寻优 | 合同指标约束下的收益/成本最优 | 同YC系列 |
| 小焦炉配比（试验配比） | 实验室小焦炉炼焦验证用 | 新方案投产前验证 | PBSJ_X |

### 6.2 生产配比（PBSJ）

**单据维度**：日期 + 炉组(PBKind) + 班次(白/中/夜) + 区号

**明细内容**：仓号、煤名、煤种、配比%，以及录入时刻的**煤质指标快照**（来自单仓煤质检）与财务价/到场价。

**表头冗余**：自动汇总七大煤类结构与国产/进口煤比例。

**保存规则**：
1. 配比合计必须等于100%，否则禁止预测与保存
2. **必须先预测后保存**——预测校验（加权→校正→公式推算全部通过）是事实上的审核环节
3. 同维度重复保存采用"先删后插"覆盖式变更
4. 保存时联动生成同单号的配合煤预测(YCCoal)、焦炭预测(YCCoke)、化产品预测(YCProduct)

**查询容错**：查不到当日配比时自动回退到最近一个有配比单的日期并提示——体现"配比在未变更期间持续有效"。

### 6.3 人工配比与配比规划（YCPB）

**人工配比**：手工录入或Excel粘贴各煤种比例 → 预测（校验ΣPB=100 → 加权 → 校正 → 分炉组焦炭公式 → 化产品公式 → 配煤结构）→ 保存。

**配比规划**：读入某日生产配比作为候选煤清单 → 为每种煤设定配比变动区间 → 自动带出最新合同指标与产品价格 → 执行优化寻优（见第7章）→ 结果走"预测→保存"流程。

> 人工配比是"参谋"，生产配比是"命令"；两者结构平行，共享同一套预测结果表。

### 6.4 配比与质检的闭环勾稽（BillID回填机制）

这是系统实现"预测↔实测"对比的关键设计：

1. 入炉煤质检(RLM)与焦炭质检(PBCoke)记录初始不带配比单号
2. 通过"配合煤对应配比录入"和"焦炭对应配比录入"功能，把某日某期的质检记录**挂接到当时执行的配比单**上（回填BillID）
3. 挂接后同一界面三栏并列展示：**实测指标 ↔ 配比明细 ↔ 预测指标**
4. 形成两段闭环：
   - 前段：入炉煤实测(RLM) ↔ 配合煤预测(YCCoal) → 修正RLMmodel校正系数w1/w2
   - 后段：焦炭实测(PBCoke) ↔ 焦炭预测(YCCoke) → 验证与修正分炉组回归公式

### 6.5 小焦炉试验线

与大生产完全平行的简化闭环：
```
试验配比(PBSJ_X，一天一单) → 试验入炉煤(RLM_X，含堆密度、细度、结焦时间) → 试验焦炭(PBCoke_X，含成焦率与LJ1~LJ4粒级分布)
```
- 采用独立的小焦炉预测公式（见第7.4.4节）
- 业务定位：新配比方案**投产前**的实验室验证手段，降低大生产试错成本

## 第7章 数学模型（完整公式与计算示例）

> 本章是系统的算法核心，所有公式均给出变量定义、计算步骤和数值示例，算法工程师可直接照此编码。

### 7.1 推算链条总览

```
各单煤指标 × 配比
      │  ① 加权平均
      ▼
配合煤加权指标
      │  ② 线性校正（RLMmodel：w1 × 加权值 + w2）
      ▼
入炉煤预测指标（RLM / YCCoal）
      │  ③ 分炉组回归公式（一期 / 二期 / 小焦炉 / 通用两阶段）
      ▼
焦炭预测指标（M40、M25、M10、Ad、S、CRI、CSR）
      │  ④ 产率公式（各期共用）
      ▼
化产品预测指标（成焦率、LA、JY、CB）
```

### 7.2 第一步：加权平均

**公式**：
```
加权值(X) = Σ(Xi × PBi) / ΣPBi
```
其中Xi为第i种煤的指标值，PBi为第i种煤的配比(%)。规划场景ΣPB恒为100，因此分母=100。

**适用指标**：Ad、V、S、G、Y、X、b、R、M、CRI、CSR、财务价、到场价。

**计算示例**：
```
两种煤配煤：煤A(Ad=10.0, 配比60%)，煤B(Ad=11.0, 配比40%)
加权Ad = (10.0×60 + 11.0×40) / 100 = 10.4%
```

结果逐项保留两位小数。

### 7.3 第二步：线性校正（RLMmodel模型）

**为什么需要校正**：加权平均值与实际入炉煤化验值之间存在系统偏差（来自粉碎细度、混合均匀性、取样代表性等因素）。

**公式**：
```
校正值 = w1 × 加权值 + w2
```

**适用变量**：Ad、V、S、G、Y、b（X、a、CRI、CSR、R、M不校正直接透传）。

**系数维护**：
- 按变量+日期维护，计算时取**最新一版**
- 查不到系数时默认w1=1、w2=0（不校正）
- 系数通过"配合煤实测(RLM)↔加权推算"的历史偏差回归确定

### 7.4 第三步：焦炭质量预测

系统支持四套预测公式，按配比种类/炉组选择：

| 公式组 | 适用场景 | 自变量 | 本版本状态 |
|---|---|---|---|
| 通用公式(Pattern1) | RLM推算及通用场景 | 校正后入炉煤指标 | **仅Ad_c、S_c启用**（M40/M10/CRI/CSR含G/Y，不启用） |
| 一期模型 | 1#2#焦炉 | 含b²、X、G/Y比值 | **不启用**（依赖G/Y/X/b） |
| 二期模型 | 3#4#焦炉 | 含S²、G·Y交互、(X-Y) | **不启用**（依赖G/Y/X） |
| 小焦炉模型 | 小焦炉试验 | 多元高次，含(b+30)归一化 | **不启用**（依赖G/Y/b） |
| 两阶段回归模型 | 无歧义描述模型 | 中间预测数据→一元回归 | **不启用**（z3-z6需单煤M40/M10/CRI/CSR） |

> **本版本说明**：用户指定忽略G（粘结指数）、X（最终收缩度）、Y（胶质层厚度）。因此所有依赖G/Y/X/b的焦炭强度预测公式（M40、M10、CRI、CSR）均不启用。仅保留通用公式中的**焦炭灰分Ad_c**和**焦炭硫分S_c**预测（仅依赖Ad、Vdaf、St.d，均为线性/简单非线性）。焦炭质量约束仅施加Ad_c和S_c。

#### 7.4.1 通用公式（Pattern1）

```
M40 = 73.78 − 0.46·V·(100−Ad)/100 + 0.14·(G+13) + 11.5        ← 本版本不启用（含G）
M25 = 106.5 − 0.529·V + 0.0136·G + 0.011·Y                   ← 本版本不启用（含G/Y）
M10 = 5.98 + 0.23·V·(100−Ad)/100 − 0.022·(G+13) − 4          ← 本版本不启用（含G）
Ad焦 = Ad / [(100−V)/0.989 + 0.9] × 100                       ← 本版本启用
S焦  = S × 0.7 / [(100−V)/0.989 + 0.9] × 100                  ← 本版本启用（0.7=硫转入焦炭比例）
CRI = 0.239·V − 0.0353·G − 0.035·Y + 22.5                    ← 本版本不启用（含G/Y）
CSR = 0.483·V + 0.011·Y + 0.413·G + 18                        ← 本版本不启用（含G/Y）
```

其中分母`[(100−V)/0.989 + 0.9]`为**干煤→焦炭质量换算系数**（挥发分烧损+焦油等损耗的经验折算）。

> **本版本仅启用Ad焦和S焦两项**，其余M40/M25/M10/CRI/CSR因含G或Y，按用户要求忽略。

> **已知问题**：通用公式CRI首项部分资料为`0.239·Y`，疑为历史笔误，建议核对原始回归资料后修正。系统应支持系数可配置。

#### 7.4.2 一期模型（1#2#焦炉）—— 本版本不启用

> 以下公式依赖G、Y、X、b，本版本按用户要求忽略，不启用。公式保留供后续数据补充后使用。

```
M40 = −3.07·V + 0.18126·G + 0.00227·b² + 161.8756
M25 = −0.0369·V + 0.04473·G + 0.0594·Y + 89.4562
M10 = −0.0314·G − 0.0666·Y + 8.91751
Ad  = 0.69335·Ad + 0.01226·V·Ad + 2.7742
S   = 0.83133·S − 0.01012·V + 0.35844
CRI = −0.089·G − 0.6096·Y + 0.24102·X + 34.8067
CSR = 3.94023·(G/Y) + 0.16445·G + 0.40192·Y − 0.1765·X + 41.0173
```

**特点**：引入奥阿膨胀度b（平方项）与最终收缩度X；CSR含G/Y比值项，Y缺失或为0时产生除零异常，录入环节须保证Y值完整，公式层应增加保护（Y<0.1时按0.1处理或返回错误提示）。

#### 7.4.3 二期模型（3#4#焦炉）—— 本版本不启用

> 以下公式依赖G、Y、X，本版本按用户要求忽略，不启用。公式保留供后续数据补充后使用。

```
M40 = 0.027·G + 0.0948·Y − 0.073·V + 84.343
M25 = 106.5 − 0.529·V + 0.0136·G + 0.011·Y
M10 = 0.0717·V − 0.008·G − 0.068·Y + 5.474
Ad  = 0.82973·Ad + 0.00983·V·Ad + 2.14513
S   = 0.52884·S + 0.015256·S² + 0.20271
CRI = −0.039·G − 0.205·Y − 0.0006·G·Y + 0.0525·(X−Y) + 31.412
CSR = 6.2329·(G/Y) + 0.0832·G + 2.6775·Y − 0.042·X − 12.08
```

**与一期差异**：硫分为二次式；CRI含G·Y交互项与(X-Y)收缩差项；CSR的G/Y系数更大。

#### 7.4.4 小焦炉试验模型 —— 本版本不启用

> 以下公式依赖G、Y、b，本版本按用户要求忽略，不启用。公式保留供后续数据补充后使用。

```
M40 = −0.102·V + 0.014·V·G + 0.021·(b+30) − 0.018·G·Y − 0.516·G/(b+30) + 78.723
M10 = 0.306·V − 0.084·G − 0.994·Y − 0.022·(b+30) + 19.407 − 0.96
```

#### 7.4.5 两阶段回归模型（无歧义描述模型）—— 本版本不启用

> 以下模型z3-z6需单煤M40/M10/CRI/CSR数据，且间接依赖G/Y，本版本按用户要求忽略，不启用。公式保留供后续数据补充后使用。

这是独立于上述分炉组公式的另一套预测方法，结构更简单，适合数据量有限时使用。

**第一阶段：中间预测数据计算**

对6个指标，按配比加权平均后乘以修正系数：

```
z1 = (1.3/100) × Σ(c1,i × xi)    // Ad预测（修正系数1.3，灰分富集效应）
z2 = (0.9/100) × Σ(c2,i × xi)    // St.d预测（修正系数0.9，硫挥发损失）
z3 = (1/100) × Σ(c3,i × xi)      // M40预测（修正系数1.0）
z4 = (1/100) × Σ(c4,i × xi)      // M10预测（修正系数1.0）
z5 = (1/100) × Σ(c5,i × xi)      // CRI预测（修正系数1.0）
z6 = (1/100) × Σ(c6,i × xi)      // CSR预测（修正系数1.0）
```

其中c_{j,i}为第i种煤的第j个指标值，xi为配比(%)。

**第二阶段：焦炭质量回归预测**

```
y1 = 0.1651 + 0.7610 × z2    // 焦炭全硫St,d
y2 = 82.00  + 0.0613 × z3    // 焦炭M40
y3 = 6.151  - 0.0154 × z4    // 焦炭M10
y4 = 9.79   + 0.4717 × z5    // 焦炭CRI
y5 = 64.93  + 0.0245 × z6    // 焦炭CSR
```

**矩阵形式**：
```
z = α ⊙ (C · w / 100)
y = β0 + β ⊙ z_selected
```
其中α=[1.3, 0.9, 1.0, 1.0, 1.0, 1.0]^T，β0=[0.1651, 82.00, 6.151, 9.79, 64.93]^T，β=[0.7610, 0.0613, -0.0154, 0.4717, 0.0245]^T。

> **本版本数据范围（用户指定）**：忽略G（粘结指数）、X（最终收缩度）、Y（胶质层厚度），仅使用原煤质量数据中的**水分、Ad、Vdaf、St.d、FCad、Mad、Cad、Had**（7977条记录，51个煤种）。因此：
> - 分炉组公式（一期/二期/小焦炉）和两阶段模型因依赖G/Y/X/b，**本版本全部不启用**
> - 通用公式中仅**Ad焦、S焦**两项启用（仅依赖Ad、Vdaf、St.d）
> - 配合煤质量约束仅施加**Ad、Vdaf、St.d**三项
> - 焦炭质量约束仅施加**Ad_c、S_c**两项
> - 系统应在G/X/Y相关指标处明确提示"本版本忽略该指标"，不得编造数值

### 7.5 第四步：化产品产率公式（各炉组共用）

化产品产率全部为挥发分V的**二次经验函数**：

```
成焦率 ηd = 100 / [(100−V)/0.989 + 0.9]
硫铵 LA = 0.144·V − 1.8 − 0.0016·V²
焦油 JY = 1.53·V − 19.4 − 0.026·V²
粗苯 CB = 0.144·V − 1.82 − 0.0016·V²
```

煤气(MQ)、焦粉(JF)、焦丁(JC)、电耗(Dian)无产率公式，仅在收益计算中按价格参与。

**计算示例**：
```
配合煤Vdaf=28%
成焦率 = 100 / [(100-28)/0.989 + 0.9] = 100 / (72.8 + 0.9) = 100/73.7 = 1.357 → 135.7%? 
```
> 注意：此处V应为干基挥发分Vd（=Vdaf×(1-Ad/100)），而非干燥无灰基Vdaf。实际计算时需注意基准换算。成焦率典型值约72-78%。

### 7.6 配比优化算法

#### 7.6.1 问题定义

给定n种候选煤及其配比变动区间，在焦炭质量满足合同指标的约束下，求**成本最低**（或**收益最大**）的配比组合。

#### 7.6.2 算法一：全枚举递归搜索（设计说明书原有算法）

- **搜索空间**：n种煤=n层递归；每种煤配比在[下限,上限]内以**1个百分点为步长**枚举
- **闭合约束**：ΣPB=100，不满足的组合直接丢弃
- **推算**：满足闭合后依次执行加权平均→RLMmodel校正→按炉组选公式计算预测焦炭指标与化产品产率
- **质量约束（七项同时满足）**：
  ```
  M40 ≥ 合同值    M25 ≥ 合同值    M10 ≤ 合同值
  CSR ≥ 合同值    CRI ≤ 合同值    Ad ≤ 合同值    S ≤ 合同值
  ```
- **目标函数（最大化，原有设计）**：
  ```
  收益 = p电·Dian + p焦油·JY + p粗苯·CB + p硫铵·LA + p煤气·MQ + p焦粉·JF + p焦丁·JC
  ```
  > 原有设计的目标函数为**产品端毛收益**，未扣除配煤成本。"最优配比"的准确语义是"焦炭质量达标前提下化产品产值最大"，而非全成本利润最大。

- **求解规则**：遍历全部可行解，保留收益严格最大的唯一组合；无可行解时提示"焦炭不能达到合同指标，无法得出最优配比，请修改合同指标或重新选煤"
- **复杂度**：组合数=Π(区间宽度+1)，区间开宽时计算量指数增长，属已知性能约束

#### 7.6.3 算法二：线性规划（LP，推荐用于成本最低目标）

当所有约束均为线性时（Ad、St.d、Vdaf约束，煤种结构约束，供应量约束），使用线性规划求解。

**决策变量**：xi = 第i种煤干基质量分数，xi≥0，Σxi=1

**目标函数（成本最低）**：
```
min C = Σ(pi^d × xi)
```
其中pi^d为干基等效单价。若价格为湿基吨价且提供了Mt：
```
pi^d = pi^wet / (1 - Mt_i/100)
```

**约束**：
```
配合煤质量：Lk ≤ Σ(qk,i × xi) ≤ Uk    （对每个有区间要求的指标k）
煤种结构：Lj ≤ Σ_{i∈Sj} xi ≤ Uj        （对每个煤类集合Sj）
供应量：xi × D ≤ si                      （若提供周期总需求D和可供量上限si）
配比闭合：Σxi = 1, xi ≥ 0
```

**求解器**：`scipy.optimize.linprog(method='highs')` 或 PuLP。

**湿基称量比例换算**（供配煤槽下料使用）：
```
wi = (xi / (1 - Mt_i/100)) / Σ_j(xj / (1 - Mt_j/100))
```

#### 7.6.4 算法三：非线性规划（当焦炭质量约束涉及非线性公式时）

当使用分炉组公式（含G/Y比值、交互项、二次项）或两阶段模型的z3-z6约束时，问题转为非线性规划。

**求解策略**：
1. 先用`scipy.optimize.differential_evolution`全局搜索（种群大小≥15n，迭代≥1000）
2. 再用`scipy.optimize.minimize(method='SLSQP')`精化
3. 输出中声明：求解结果可能受公式形式影响，建议多次运行取最优

**边界保护**：
- G/Y比值项：Y<0.1时按0.1处理或返回不可行
- b+30归一化：b<-29时按-29处理
- 所有变量 bounds 与配比约束一致

#### 7.6.5 无可行解诊断

当优化无可行解时，系统必须：
1. 不输出配比方案
2. 诊断冲突约束组合，至少列出一组：
   - G下限与低G煤结构约束冲突
   - 硫上限与高硫煤结构下限冲突
   - 灰分上限与高灰煤使用冲突
   - 库存可用量不足（某煤种需求超过库存+在途）
   - 煤种结构约束互斥（如主焦煤下限+主焦煤库存不足）
3. 给出至少一条可操作的放宽建议

### 7.7 配煤结构统计

按煤种名称关键字把各煤配比归并为七大煤类占比（肥煤、主焦、1/3焦、瘦煤、弱粘、瘦焦、气煤），用于配比方案的结构合理性展示。关键字独立判断，一个煤名可能命中多个类别，结果不归一化。

### 7.8 反推功能（FrmBinfer）

提供由目标反推的辅助计算：给定入炉煤指标与部分煤种，反推配合煤/单种煤指标，按一期/二期选择对应公式组，用于单煤置换评估与方案微调。

## 第8章 排程-配煤联动测算

### 8.1 联动总体流程

```
Step 1: 数据采集（库存快照+船运在途+铁运在途+近两个月质量+价格+合同指标）
Step 2: 数据清洗与映射（A2/G3编码统一、质量聚合、在途到货预测、日均消耗计算）
Step 3: 水位线评估（各煤种库存当量→水位线等级→预警清单）
Step 4: 进销存粗排程（模式A：历史均值消耗，15天推演，识别断料风险日）
Step 5: 配煤优化（候选煤=有库存+近期在途到货，可用量=库存+周期内到货，求解成本最低配比）
Step 6: 精确排程（模式B：用最优配比消耗量替换历史均值，重新推演15天库存曲线）
Step 7: 验证与迭代（所有煤种库存非负且不跌破最低线？若不满足，调整配比或生成采购建议，返回Step 5）
Step 8: 输出（配比方案+质量预测+排程表+水位线预警+采购建议）
```

### 8.2 联动核心约束

排程约束配煤：配煤优化的**可用量上限** = 当前库存 + 排程周期内在途到货。配比方案不能使用超出可用量的煤种。

配煤修正排程：配煤方案确定后，各煤种日消耗量由配比决定，重新推演库存曲线，验证是否断料。若断料则反馈调整配比（降低短缺煤种比例，增加替代煤种）。

**迭代终止条件**：所有煤种在排程周期内库存当量 ≥ 最低库存线，且配比方案满足所有质量约束。

### 8.3 排程预留缓冲（五类）

配煤排程必须在常规生产计划基础上预留缓冲余量：

| 缓冲类型 | 预留量 | 说明 |
|---|---|---|
| 运输缓冲 | 船运+2天，铁运+1天 | 应对港口压船、铁路调度延误 |
| 煤种切换缓冲 | ≥1天混配过渡 | 新旧批次切换时避免煤质突变 |
| 检测周期缓冲 | ≥24小时 | 新到厂煤料从接卸到完成全指标检测 |
| 设备检修缓冲 | ≥3天已混匀配合煤储备 | 配煤设备定期检修期间 |
| 极端天气缓冲 | 关键煤种安全库存上浮至12天 | 汛期、冬季冻煤、台风期间 |

排程预留量纳入月度生产计划考核，不得因压缩成本而削减缓冲余量。每周召开配煤排程平衡会，核对库存、在途、消耗三方数据。

## 第12章 异常与边界处理

### 12.1 数据异常

| 异常场景 | 处理方式 |
|---|---|
| 库存快照缺失某日 | 使用最近一日库存前推，标记"估算值" |
| 船运预计到港时间=在途开始时间（异常） | 按航线标准周期推算，标记"推算值" |
| 铁运发出时间格式异常 | 尝试多种格式解析，失败标记"待人工确认" |
| 质量数据某煤种缺Ad/Vdaf/St.d | 该煤种不纳入配煤候选，标记"质量数据不全" |
| 质量数据缺G | 分炉组公式无法完整运行，输出中声明"G缺失，M40/M10/CRI/CSR未预测" |
| 质量数据缺单煤M40/M10/CRI/CSR | 两阶段模型z3-z6无法计算，声明缺失 |
| 同一煤种多个库区库存 | 按品名中文汇总 |
| 在途记录已到厂但状态未更新 | 按到厂_进厂交接时间非空过滤，不计入在途 |
| Y=0导致G/Y除零 | 公式层保护：Y<0.1时按0.1处理或返回错误提示 |

### 12.2 业务异常

| 异常场景 | 处理方式 |
|---|---|
| 配比合计≠100% | 禁止预测与保存，提示具体差额 |
| 配比预测不满足合同指标 | 禁止保存为生产配比，显示不满足的指标项 |
| 优化无可行解 | 不输出配比，诊断冲突约束组合，给出放宽建议 |
| 某煤种配比需求超过可用量 | 优化时约束不可行，提示该煤种缺口量，建议采购或调整 |
| 排程推演出现负库存 | 标红预警，生成采购建议，提示调整配比 |
| 煤名不在煤归类表中 | 库存录入时标红拒绝保存 |
| 删除已有质检数据的煤名 | 禁止删除，提示"该煤名已有质检数据" |

### 12.3 性能边界

| 场景 | 约束 | 建议 |
|---|---|---|
| 全枚举优化 | 组合数=Π(区间宽度+1)，指数增长 | 候选煤≤8种、区间宽度≤10时可用全枚举；否则用LP/启发式 |
| 非线性优化 | differential_evolution迭代次数大 | 种群大小=15n，最大迭代=1000，超时设为60秒 |
| 排程推演 | 15天×N煤种，线性复杂度 | 无性能问题，可支持50+煤种 |
| 质量数据聚合 | 7700+条记录 | 按品名编码+化验项目预计算均值，缓存到质量汇总表 |

### B.1 加权平均
```
加权值 = Σ(Xi × PBi) / 100
```

### B.2 RLM校正
```
校正值 = w1 × 加权值 + w2
```

### B.3 干煤→焦炭换算系数
```
K = (100 - V) / 0.989 + 0.9
```

### B.4 焦炭灰分/硫分（通用公式）
```
Ad焦 = Ad / K × 100
S焦  = S × 0.7 / K × 100
```

### B.5 成焦率
```
ηd = 100 / K
```

### B.6 干基等效价
```
p_dry = p_wet / (1 - Mt/100)
```

### B.7 湿基称量比例
```
wi = (xi / (1 - Mt_i/100)) / Σ_j(xj / (1 - Mt_j/100))
```
